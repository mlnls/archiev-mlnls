## 트리라는 모양

[[트리]]는 노드들이 부모-자식 관계로 이어진 구조입니다. 맨 위에 부모가 없는 노드가 하나 있고(루트), 나머지 노드는 모두 부모가 정확히 하나입니다. 그래서 고리가 없고, 루트에서 어떤 노드로 가는 길은 하나뿐입니다.

```text
            html            ← 루트
          /      \
       head      body       ← html의 자식들 (서로 형제)
        |       /    \
      title   h1      p     ← 자식이 없는 노드: 리프
```

| 말 | 뜻 |
| --- | --- |
| 루트 | 부모가 없는 맨 위 노드 |
| 리프 | 자식이 없는 노드 |
| 깊이 | 루트에서 그 노드까지 내려가는 간선 수 |
| 높이 | 트리에서 가장 깊은 리프의 깊이 |
| 서브트리 | 어떤 노드와 그 모든 자손으로 된 작은 트리 |

트리의 연산 속도는 대개 높이에 달려 있습니다. 노드 n개를 잘 퍼지게 두면 높이가 log n 정도라서, 루트에서 찾아 내려가는 일이 O(log n)에 끝납니다. 100만 개여도 20단계입니다.

## 이진 트리와 순회

자식이 많아야 둘인 트리를 [[이진 트리]]라고 합니다. 트리의 모든 노드를 한 번씩 방문하는 것을 [[트리 순회]]라고 하고, 방문 순서에 따라 이름이 다릅니다.

| 순회 | 순서 | 쓰임 |
| --- | --- | --- |
| 전위 (pre-order) | 나 → 왼쪽 → 오른쪽 | 트리 복사, DOM의 문서 순서, 목차 출력 |
| 중위 (in-order) | 왼쪽 → 나 → 오른쪽 | 이진 탐색 트리를 정렬된 순서로 |
| 후위 (post-order) | 왼쪽 → 오른쪽 → 나 | 자식을 먼저 처리해야 할 때: 폴더 크기 합, 트리 지우기 |
| 레벨 순서 | 깊이 1, 2, 3… 차례로 | 가까운 것부터. 큐를 씀 |

앞의 세 가지는 재귀로 쓰면 그대로 읽힙니다.

```js
function preorder(node, visit) {
  if (!node) return;                  // 기저 사례 (20장)
  visit(node);
  for (const child of node.children) preorder(child, visit);
}

// DOM에서 모든 텍스트를 문서 순서대로 모으기
const texts = [];
preorder(document.body, (n) => n.nodeType === Node.TEXT_NODE && texts.push(n.textContent));
// (실제 DOM 노드는 children 대신 childNodes를 씁니다)
```

`document.querySelectorAll`이 돌려주는 순서, 8장의 `du`가 폴더 크기를 셀 때(후위), 화면 읽기 프로그램이 페이지를 읽는 순서(전위)가 모두 트리 순회입니다. 트리가 아주 깊으면 재귀가 스택 오버플로(5장)를 낼 수 있으니 18장의 스택을 직접 써서 반복문으로 바꿉니다.

## 이진 탐색 트리

[[이진 탐색 트리]](BST)는 모든 노드에서 "왼쪽 서브트리의 값 < 나 < 오른쪽 서브트리의 값"이 지켜지는 이진 트리입니다. 찾을 때는 루트에서 시작해 작으면 왼쪽, 크면 오른쪽으로 내려가면 됩니다. 매 단계 후보가 절반쯤 줄어드니 O(log n)입니다. 중위 순회하면 정렬된 순서로 나옵니다.

```text
        8
      /   \
     3     10        6을 찾기: 8보다 작다 → 왼쪽, 3보다 크다 → 오른쪽, 찾음
    / \      \
   1   6      14
```

문제는 넣는 순서입니다. 1, 2, 3, 4, 5처럼 정렬된 값을 차례로 넣으면 모두 오른쪽으로만 붙어 한 줄짜리 트리가 되고, 높이가 n이 되어 O(n)으로 떨어집니다. 그래서 넣고 뺄 때마다 트리를 조금씩 회전시켜 높이를 log n으로 유지하는 [[균형 이진 탐색 트리]]를 씁니다. AVL 트리와 [[레드-블랙 트리]]가 대표적입니다.

균형 트리는 "정렬된 상태를 유지하면서 넣고 빼고 찾기를 모두 O(log n)"에 하고 싶을 때 씁니다.

- Linux 커널의 스케줄러(6장)는 실행할 스레드들을 레드-블랙 트리에 두고, 가장 덜 실행된 스레드를 맨 왼쪽에서 바로 꺼냅니다.
- Java의 `TreeMap`, C++의 `std::map`이 레드-블랙 트리입니다.
- JS에는 정렬된 맵이 기본으로 없어서, 필요하면 라이브러리를 쓰거나 정렬된 배열과 이진 탐색(20장)으로 대신합니다.

## 힙과 우선순위 큐

"가장 급한 것부터 꺼내기"가 필요할 때가 많습니다. 넣는 순서가 아니라 우선순위 순서로 꺼내는 큐를 [[우선순위 큐]]라고 하고, 보통 [[힙]]으로 만듭니다.

최소 힙은 "부모 ≤ 자식"이 모든 곳에서 지켜지는 이진 트리입니다. 그래서 루트가 늘 가장 작습니다. 형제끼리는 순서가 없어서 BST보다 느슨하지만, 그만큼 유지가 쉽습니다. 그리고 빈틈없이 왼쪽부터 채운 트리라서 배열 하나에 담을 수 있습니다. i번 노드의 자식은 2i+1, 2i+2번, 부모는 (i−1)/2번입니다.

```text
배열 [1, 3, 2, 7, 4, 5]  =        1
                               /   \
                              3     2
                             / \   /
                            7   4 5
```

- **넣기**: 맨 끝에 넣고, 부모보다 작으면 부모와 자리를 바꾸며 위로 올립니다. O(log n).
- **꺼내기**: 루트(최솟값)를 꺼내고, 맨 끝 원소를 루트에 올린 뒤 더 작은 자식과 바꾸며 아래로 내립니다. O(log n).
- **최솟값 보기**: 루트. O(1).

힙은 생각보다 가까이에 있습니다.

- **타이머**: Node의 libuv는 `setTimeout`들을 만료 시각 기준 최소 힙에 둡니다. 이벤트 루프는 루트만 보면 "다음에 깨어날 시각"을 압니다.
- **React의 스케줄러**: 할 일들을 마감 시각 기준 최소 힙에 넣고 가장 급한 것부터 처리합니다.
- **상위 k개**: 100만 개 중 점수 상위 10개는 전부 정렬(O(n log n))하지 않고 크기 10짜리 힙으로 O(n log 10)에 구합니다.

## 트라이

[[트라이]]는 문자열을 글자 단위로 나눠 트리로 저장하는 구조입니다. 같은 접두사를 가진 문자열들이 같은 가지를 나눠 씁니다.

```text
(루트) ─ c ─ a ─ r ●        "car", "cart", "cat", "dog"
             │    └ t ●
             └ t ●
       ─ d ─ o ─ g ●        ● = 여기서 끝나는 단어가 있음
```

"이 접두사로 시작하는 모든 단어"를 접두사 길이만큼만 내려가서 찾습니다. 검색창 자동 완성이 대표적인 쓰임입니다. 웹 서버 프레임워크의 URL 라우터(Fastify, Hono 등)도 경로를 트라이 변형(래딕스 트리)에 넣어 요청 경로에 맞는 처리 함수를 빠르게 찾습니다. 11장의 라우팅 테이블에서 최장 접두사 일치를 하는 것도 IP 주소의 비트를 따라 내려가는 트라이입니다. Linux 커널의 라우팅 테이블이 실제로 이렇게 생겼습니다.

## B-트리: 디스크를 위한 트리

이진 트리는 노드 하나에 값이 하나라 높이가 log₂ n입니다. 메모리에서는 괜찮지만, 노드 하나를 읽을 때마다 디스크를 읽어야 한다면 이야기가 다릅니다. 2장의 숫자표에서 디스크 읽기는 메모리 읽기보다 수백~수만 배 느렸습니다. 100만 개를 이진 트리로 찾으면 디스크를 20번 읽습니다.

[[B-트리]]는 노드 하나에 키를 수백 개 넣고 자식도 수백 개 두는 균형 트리입니다. 노드 크기를 디스크가 한 번에 읽는 페이지(4KB, 8KB, 16KB)에 맞춥니다. 자식이 500개씩이면 높이 3으로 1억 개를 담습니다. 위쪽 노드들은 메모리에 캐시해 두니, 실제 디스크 읽기는 한두 번으로 끝납니다.

[[B+트리]]는 실제 데이터(또는 데이터 위치)를 모두 리프에만 두고, 리프끼리 옆으로 이어 둔 B-트리입니다. "10 이상 20 이하"처럼 범위를 찾을 때 시작점까지 내려간 뒤 리프를 옆으로 따라가기만 하면 됩니다. 21장에서 볼 데이터베이스 인덱스가 거의 다 B+트리이고, NTFS, APFS, ext4의 디렉터리 같은 파일 시스템 구조에도 B-트리 계열이 쓰입니다.

## 그래프

트리에서 "부모는 하나, 고리 없음"이라는 제약을 풀면 [[그래프]]가 됩니다. 노드(정점)와 그 사이를 잇는 간선의 모음입니다.

- **방향**: 간선에 방향이 있으면 방향 그래프(팔로우, 의존 관계), 없으면 무방향 그래프(친구, 도로).
- **가중치**: 간선에 비용이 붙으면 가중 그래프(거리, 지연 시간).
- **고리**: 방향 그래프에 고리가 없으면 [[DAG]](방향 비순환 그래프)라고 합니다. 의존 관계와 작업 순서가 대개 DAG입니다.

이 책에 나온 그래프들입니다.

| 그래프 | 정점 | 간선 |
| --- | --- | --- |
| 인터넷 (11장) | 라우터, AS | 회선. 가중치는 비용이나 지연 |
| 모듈 의존성 (5장의 번들러) | 파일 | import. DAG여야 좋음 |
| npm 패키지 | 패키지 | 의존 |
| Git 커밋 (25장) | 커밋 | 부모 커밋. DAG |
| 웹 | 페이지 | 링크 |
| 상태 기계 | 상태 | 전이 (로딩 → 성공, 로딩 → 실패) |

그래프를 저장하는 방법은 둘입니다.

| | [[인접 리스트]] | [[인접 행렬]] |
| --- | --- | --- |
| 모양 | 정점마다 이웃 목록 (`Map<정점, 이웃[]>`) | V × V 표에 연결되면 1 |
| 메모리 | O(V + E) | O(V²) |
| "둘이 이어져 있나?" | 이웃 목록을 훑음 | O(1) |
| 어울리는 경우 | 간선이 적은 대부분의 실제 그래프 | 정점이 적고 간선이 빽빽할 때 |

## 너비 우선 탐색과 깊이 우선 탐색

그래프의 정점들을 빠짐없이 돌아보는 기본 방법이 둘 있습니다. 둘 다 이미 방문한 정점을 기억해서(18장의 `Set`) 고리를 만나도 같은 곳을 다시 돌지 않습니다. 둘 다 O(V + E)입니다.

**[[너비 우선 탐색]]**(BFS)은 시작점에서 가까운 정점부터 한 겹씩 넓혀 갑니다. 큐를 씁니다. 간선에 가중치가 없으면, 처음 도착했을 때의 거리가 곧 최단 거리입니다.

```js
function shortestHops(graph, start, goal) {
  const dist = new Map([[start, 0]]);
  const queue = [start];
  for (let i = 0; i < queue.length; i++) {        // 18장의 앞 번호 큐
    const v = queue[i];
    if (v === goal) return dist.get(v);
    for (const w of graph.get(v) ?? []) {
      if (!dist.has(w)) { dist.set(w, dist.get(v) + 1); queue.push(w); }
    }
  }
  return -1;
}
```

**[[깊이 우선 탐색]]**(DFS)은 한 방향으로 갈 수 있는 데까지 들어갔다가, 막히면 돌아와 다른 길로 갑니다. 스택(또는 재귀)을 씁니다. 연결된 덩어리 찾기, 고리 찾기, 미로 풀기, 아래의 위상 정렬에 씁니다. 트리 순회의 전위, 후위는 트리에서 하는 DFS입니다.

| | BFS | DFS |
| --- | --- | --- |
| 쓰는 구조 | 큐 | 스택, 재귀 |
| 방문 순서 | 가까운 것부터 | 깊은 것부터 |
| 잘하는 것 | 가중치 없는 최단 거리, 몇 단계 친구 | 고리 찾기, 위상 정렬, 모든 경로 탐색 |

## 위상 정렬: 순서가 있는 일 줄 세우기

"A가 끝나야 B를 할 수 있다"는 관계들이 있을 때, 모든 관계를 지키는 순서로 일을 늘어놓는 것을 [[위상 정렬]]이라고 합니다. 고리가 없는 DAG에서만 됩니다.

```text
core ──▶ db ──▶ api
  │              ▲
  └──▶ scraper ──┘          가능한 순서: core, db, scraper, api
```

방법 하나는 "들어오는 간선이 없는 정점"(먼저 할 게 없는 일)을 큐에 넣고, 꺼낼 때마다 그 정점에서 나가는 간선을 지워 새로 들어오는 간선이 없어진 정점을 큐에 넣는 것입니다(칸의 알고리즘). 끝났는데 남은 정점이 있으면 고리가 있다는 뜻입니다.

위상 정렬은 도구들 안에서 늘 돌고 있습니다.

- 이 저장소의 빌드 도구 Turborepo는 패키지들의 의존 그래프를 위상 정렬해서 `packages/core`를 먼저, 그걸 쓰는 `apps/api`를 나중에 빌드하고, 서로 관계없는 것들은 병렬로 돌립니다.
- 번들러는 모듈을 의존 순서대로 실행되게 배치합니다. 모듈끼리 서로를 import하는 고리가 있으면 "Circular dependency" 경고가 나고, 실행 순서에 따라 아직 초기화되지 않은 값을 읽는 버그가 생깁니다.
- 스프레드시트는 셀 수식의 의존 관계를 따라 다시 계산할 순서를 정합니다.

## 최단 경로

간선에 거리나 비용이 있을 때 두 정점 사이의 가장 싼 길을 찾는 문제입니다.

- **[[다익스트라 알고리즘]]**: 시작점에서 지금까지 확정된 가장 가까운 정점을 우선순위 큐(힙)에서 꺼내고, 그 이웃들의 거리를 더 짧게 고칠 수 있으면 고칩니다. 가중치가 음수가 아니면 O((V + E) log V)에 끝납니다. 11장에서 AS 안쪽의 길을 정하는 OSPF 같은 링크 상태 라우팅 프로토콜이, 각 라우터가 네트워크 전체 지도를 받아 다익스트라로 최단 경로를 계산하는 방식입니다.
- **벨만-포드**: 음수 가중치도 다루지만 느립니다(O(VE)). 이웃에게 "나는 거기까지 이만큼"을 알려 주며 퍼지는 옛 라우팅 프로토콜(RIP)이 이 생각을 씁니다.
- **A 스타**(A*): 목적지까지 남은 거리를 어림해서 그쪽을 먼저 보는 다익스트라. 지도 길 찾기와 게임 캐릭터 이동에 씁니다.

## 그 밖의 그래프 문제

- **최소 신장 트리**: 모든 정점을 가장 적은 총비용으로 잇는 간선 묶음. 도시들을 가장 싸게 광케이블로 잇는 문제입니다. 크루스컬, 프림 알고리즘.
- **연결 요소와 유니온 파인드**: "이 둘이 같은 덩어리인가?"를 거의 O(1)에 답하는 구조. 크루스컬 알고리즘과 네트워크 연결 확인에 씁니다.
- **페이지랭크**: 링크 그래프에서 많이, 중요한 페이지로부터 링크를 받는 페이지가 중요하다는 생각. 초기 Google 검색의 바탕입니다.

## 프론트엔드와 이어지는 곳

- React의 재조정(reconciliation)은 이전 컴포넌트 트리와 새 트리를 비교해 바뀐 곳만 DOM에 반영합니다. 두 트리를 일반적으로 비교하면 O(n³)이라 너무 느려서, React는 "타입이 다르면 서브트리를 통째로 바꾼다", "형제는 `key`로 짝을 맞춘다"는 가정으로 O(n)에 합니다. `key`를 인덱스로 주면 안 되는 이유가 이것입니다.
- 댓글과 답글, 폴더 트리, 메뉴처럼 중첩된 데이터를 그릴 때는 재귀 컴포넌트를 쓰고, 서버에서 받은 평평한 목록(`parentId`가 있는)을 트리로 바꾸는 일은 `Map`으로 O(n)에 합니다.
- 폼 단계, 결제 흐름, 비동기 로딩 상태를 상태 기계(그래프)로 그려 보면 빠진 전이와 불가능한 상태가 보입니다.
- 순환 import 경고는 모듈 그래프의 고리입니다. 공통 부분을 따로 빼서 고리를 끊습니다.

## 용어 정리

:::terms
- 트리 (tree) — 루트에서 시작해 각 노드가 부모를 하나씩 가지는, 고리 없는 계층 구조입니다.
- 이진 트리 (binary tree) — 모든 노드의 자식이 많아야 둘인 트리입니다.
- 트리 순회 (tree traversal) — 트리의 모든 노드를 정해진 순서(전위, 중위, 후위, 레벨)로 한 번씩 방문하는 것입니다.
- 이진 탐색 트리 (binary search tree) — 모든 노드에서 왼쪽 값 < 노드 < 오른쪽 값이 지켜지는 이진 트리. 균형이 맞으면 찾기가 O(log n)입니다.
- 균형 이진 탐색 트리 (balanced binary search tree) — 넣고 뺄 때 회전으로 높이를 log n으로 유지하는 이진 탐색 트리. AVL, 레드-블랙 트리.
- 레드-블랙 트리 (red-black tree) — 노드에 빨강과 검정 표시를 붙여 균형을 유지하는 이진 탐색 트리. Linux 스케줄러, Java TreeMap이 씁니다.
- 힙 (heap) — 부모가 늘 자식보다 작은(또는 큰) 완전 이진 트리. 배열에 담고, 최솟값을 O(1)에 보고 O(log n)에 꺼냅니다. 7장의 메모리 영역 힙과는 다른 뜻입니다.
- 우선순위 큐 (priority queue) — 넣은 순서가 아니라 우선순위가 높은 것부터 꺼내는 큐. 보통 힙으로 만듭니다.
- 트라이 (trie) — 문자열을 글자 단위로 나눠 같은 접두사를 공유하는 트리. 자동 완성, URL 라우터, IP 라우팅에 씁니다.
- B-트리 (B-tree) — 노드 하나에 키와 자식을 많이 둬 높이를 낮게 유지하는 균형 트리. 디스크 읽기 횟수를 줄입니다.
- B+트리 (B+ tree) — 데이터를 리프에만 두고 리프끼리 이어 범위 검색이 빠른 B-트리. 데이터베이스 인덱스의 기본 구조입니다.
- 그래프 (graph) — 정점과 정점을 잇는 간선의 모음. 방향과 가중치가 있을 수 있습니다.
- DAG (Directed Acyclic Graph) — 고리가 없는 방향 그래프. 의존 관계, 작업 순서, Git 커밋 기록이 DAG입니다.
- 인접 리스트 (adjacency list) — 정점마다 이웃 정점 목록을 두는 그래프 저장 방식입니다.
- 인접 행렬 (adjacency matrix) — 정점 수 × 정점 수 표에 연결 여부를 적는 그래프 저장 방식입니다.
- 너비 우선 탐색 (BFS, Breadth-First Search) — 시작점에서 가까운 정점부터 한 겹씩 큐로 방문하는 탐색. 가중치 없는 최단 거리를 구합니다.
- 깊이 우선 탐색 (DFS, Depth-First Search) — 한 길로 끝까지 들어갔다 돌아오며 스택이나 재귀로 방문하는 탐색입니다.
- 위상 정렬 (topological sort) — DAG의 정점들을 모든 간선의 방향을 지키는 순서로 늘어놓는 것. 빌드 순서와 작업 순서를 정합니다.
- 다익스트라 알고리즘 (Dijkstra's algorithm) — 음수가 아닌 가중치 그래프에서 우선순위 큐로 한 시작점의 최단 경로를 모두 구하는 알고리즘입니다.
- 최소 신장 트리 (minimum spanning tree) — 그래프의 모든 정점을 고리 없이 가장 적은 총가중치로 잇는 간선 집합입니다.
:::

## 직접 해보기

:::practice dom-walk DOM 트리 순회하기
아무 페이지의 콘솔에서 DOM 트리의 높이(가장 깊은 노드의 깊이)와 노드 수, 가장 자식이 많은 요소를 재귀로 구합니다. 같은 일을 재귀 없이 스택으로도 짜 봅니다.

```js 브라우저 콘솔
function stats(el, depth = 0, acc = { count: 0, height: 0, widest: null }) {
  acc.count++;
  acc.height = Math.max(acc.height, depth);
  if (!acc.widest || el.children.length > acc.widest.children.length) acc.widest = el;
  for (const child of el.children) stats(child, depth + 1, acc);
  return acc;
}
stats(document.documentElement);
```
:::

:::practice heap 최소 힙 만들기
배열로 최소 힙을 만들고(`push`, `pop`, `peek`), 무작위 숫자 1만 개를 넣었다가 다 꺼냈을 때 정렬된 순서로 나오는지 확인합니다. 그다음 이 힙으로 "100만 개 중 가장 큰 10개"를 구해 `sort` 후 `slice`와 시간을 비교합니다.
:::

:::practice tree-from-list 평평한 목록을 트리로 바꾸기
서버에서 받은 댓글처럼 `{ id, parentId, text }` 목록을 트리로 바꾸는 함수를 O(n)으로 짭니다. 힌트는 `Map`으로 id에서 노드를 찾는 것입니다. 바꾼 트리를 들여쓰기로 출력해 봅니다.

```js
const comments = [
  { id: 1, parentId: null, text: "글 좋네요" },
  { id: 2, parentId: 1, text: "감사합니다" },
  { id: 3, parentId: null, text: "질문 있어요" },
  { id: 4, parentId: 2, text: "저도요" },
];
```
:::

:::practice toposort 이 저장소의 패키지 빌드 순서 구하기
`apps`와 `packages` 폴더의 `package.json`에서 `workspace:*` 의존성을 읽어 그래프를 만들고, 위상 정렬로 빌드 순서를 구합니다. 다른 모노레포라도 좋습니다. 결과를 Turborepo나 pnpm이 실제로 실행하는 순서(`pnpm -r --workspace-concurrency=1 exec pwd` 출력 순서)와 비교합니다.
:::

## 스스로 점검

:::qa 이진 탐색 트리에 1부터 10만까지 차례로 넣으면 무슨 일이 생기고, 어떻게 막나요?
매번 가장 큰 값이 들어와 모두 오른쪽 자식으로만 붙어 높이 10만의 한 줄짜리 트리가 되고, 찾기가 O(n)으로 떨어집니다. 넣고 뺄 때 회전으로 높이를 log n으로 유지하는 AVL이나 레드-블랙 트리 같은 균형 트리를 씁니다.
:::

:::qa 힙이 배열 하나에 담길 수 있는 이유와, 가장 작은 값을 꺼내는 과정은?
힙은 왼쪽부터 빈틈없이 채운 완전 이진 트리라서, i번 노드의 자식을 2i+1, 2i+2번 칸으로 계산할 수 있습니다. 꺼낼 때는 루트를 빼고 맨 끝 원소를 루트로 올린 뒤, 더 작은 자식과 자리를 바꾸며 아래로 내려 힙 성질을 되찾습니다. O(log n)입니다.
:::

:::qa 데이터베이스 인덱스가 이진 탐색 트리가 아니라 B+트리를 쓰는 이유는?
디스크에서는 노드 하나를 읽는 비용이 크니, 노드에 키를 수백 개 넣어 트리 높이를 3~4로 낮춰 디스크 읽기 횟수를 줄입니다. 리프들이 옆으로 이어져 있어 범위 검색은 시작점을 찾은 뒤 리프를 따라가기만 하면 됩니다.
:::

:::qa 가중치 없는 그래프의 최단 경로에 BFS를 쓸 수 있는 이유는? 가중치가 있으면?
BFS는 시작점에서 거리 1인 정점들, 2인 정점들 순서로 방문하니 어떤 정점에 처음 도착한 순간의 거리가 가장 짧은 거리입니다. 가중치가 있으면 간선 수와 비용이 다르니, 지금까지 가장 가까운 정점을 우선순위 큐로 고르는 다익스트라를 씁니다.
:::

:::qa 위상 정렬이 어디에 쓰이는지 세 가지와, 고리가 있으면 어떻게 되는지 말해 보세요.
모노레포 패키지 빌드 순서, 번들러의 모듈 실행 순서, 스프레드시트의 셀 재계산 순서, 작업 스케줄러의 선후 관계에 씁니다. 고리가 있으면 먼저 해야 할 일이 서로를 기다려 순서를 정할 수 없고, 도구는 순환 의존 오류나 경고를 냅니다.
:::
