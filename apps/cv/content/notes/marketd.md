## 한쪽만 바꾸면 상대편이 깨졌다

마켓:D는 관리자, 사용자 앱, 웹뷰가 각자 다른 레포에 있었다.

사용자 앱은 웹뷰를 띄운다.
그리고 둘은 메시지를 주고받는다. 웹뷰가 "로그인 화면으로 보내 줘"라고 하면 앱이 화면을 바꾸는 식이다.

## 앱과 웹뷰는 문자열로 대화한다

웹뷰와 앱 사이에는 함수 호출이 없다.
웹뷰는 `window.ReactNativeWebView.postMessage`로 문자열을 보내고, 앱은 `onMessage`로 받는다.
반대 방향도 마찬가지다.

그래서 둘 사이의 약속은 결국 "어떤 type 문자열을 보낼 것인가"다.
`WEB_LOGOUT`을 보내기로 했으면 양쪽이 정확히 같은 글자를 써야 한다.

문제는 이 약속이 양쪽 레포에 따로 적혀 있었다는 것이다.
앱에서 메시지 이름을 바꾸면 웹뷰는 그걸 모른다. 타입 검사도 레포를 넘어가지 못한다.
결과는 예고 없이 깨진 기능이었다. 반대도 마찬가지였다.

## 약속을 한 곳에만 두기

pnpm workspace와 Turborepo로 세 레포를 하나로 합쳤다.
그리고 양쪽이 같이 쓰는 것들을 공통 패키지로 뺐다.

![이전에는 세 레포에 메시지 정의 사본이 따로 있었고, 이후에는 한 워크스페이스에서 앱과 웹뷰가 같은 constants 패키지를 import하는 구조](monorepo.svg "레포 세 개에서 워크스페이스 하나로")

두 앱에 흩어져 있던 메시지 이름은 합집합으로 모아 하나로 만들었다.

```ts packages/constants/src/webview-message.ts
/**
 * Webview <-> React Native 앱 사이의 postMessage 계약(contract).
 *
 * - WEB_MSG: webview 가 RN 으로 보내는 메시지의 type
 * - APP_MSG: RN 이 webview 로 보내는 메시지의 type
 *
 * webview / mobile 양쪽이 반드시 동일한 키 셋을 공유해야 하므로

 */
export const WEB_MSG = Object.freeze({
  READY: 'READY',
  LOGOUT: 'WEB_LOGOUT',
  GO_TO_LOGIN: 'WEB_GO_TO_LOGIN',
  // ...
});
```

공통 설정과 env schema도 같은 식으로 뺐다.

## 앱은 세 겹으로 되어 있다

마켓:D 앱을 뜯어 보면 세 겹이다.

- **네이티브 바이너리**: 스토어에서 받는 앱 그 자체. 카메라 같은 기기 기능이 여기 있다
- **JS 번들**: React Native 코드. 앱과 웹뷰를 잇는 로직이 여기 있다
- **웹뷰**: 화면은 웹 주소를 불러와서 그린다

세 겹은 바뀌는 방법이 다르다.

웹뷰 화면은 웹 서버에 있으니 웹만 배포하면 된다.
네이티브 바이너리는 스토어를 거쳐야만 바뀐다.

가운데 JS 번들이 애매했다. 지금까지는 바이너리와 같이 묶여서 스토어로 나갔다.
그런데 JS 번들은 앱이 실행될 때 읽는 파일일 뿐이다. 이 파일만 새로 받게 할 수 있다.
그게 Expo EAS Update(OTA)다.

## 바뀐 것에 따라 길을 나누기

|---|---|
| 화면 (웹뷰) | 웹 배포. 스토어와 상관없이 바로 반영 |

## 무엇을 테스트할까

테스트를 짜기 전에 정한 게 있다.
"이 함수가 무엇을 리턴하나"가 아니라 "관리자가 무엇을 하면 화면이 어떻게 되나"를 테스트한다.

관리자에게 중요한 건 버튼을 누르면 목록이 바뀌고, 저장하면 알림이 뜨는 것이다.
그래서 화면 단위로, 실제 사용 흐름대로 통합 테스트를 짰다.

## 서버 대신 MSW

화면 테스트에는 서버 응답이 필요하다.
그렇다고 화면 코드 안에 "테스트면 가짜 데이터" 같은 분기를 넣고 싶지는 않았다.

MSW는 요청이 나가는 길목에서 가로채서 대신 응답한다.
화면 코드는 실제로 `fetch`를 부르고, 실제 응답처럼 받는다. 테스트인 줄 모른다.

![테스트가 실제 관리자 화면을 그리고, 화면의 실제 fetch 요청을 MSW가 가로채 fixture로 응답하는 흐름](msw.svg "MSW가 끼어드는 자리")

- 도메인별로 fixture를 만들었다
- alert · table · download처럼 자주 하는 확인은 공통 유틸로 뺐다
- 테스트 이름은 "~하면 ~한다" 문장으로 썼다

마지막 규칙 덕분에 테스트 목록을 위에서부터 읽으면 그대로 요구사항 목록이 된다.

## jsdom은 브라우저가 아니다

통합 테스트는 jsdom에서 돈다.
jsdom은 브라우저의 DOM을 JS로 흉내 낸 것이다. 빠르지만, 브라우저가 하는 일을 전부 하지는 않는다.

걸린 곳은 업로드였다.
jsdom은 File을 멀티파트로 바꿀 때 파일명과 내용을 잃는다.
업로드가 제대로 되는지는 통합 테스트로 확인할 수 없었다.

## 전부 옮기지 않기

그렇다고 테스트를 전부 브라우저로 옮기지는 않았다.
브라우저 테스트는 느리고, 느린 테스트는 덜 돌린다.

그래서 기준을 세웠다. **jsdom이 흉내 내지 못하는 곳만 브라우저로.**

| 확인할 것 | 어디서 | 이유 |
|---|---|---|
| 목록 · 필터 · 저장 · 알림 | 통합 테스트 (jsdom) | DOM과 요청만 보면 된다 |
| 배너 이미지 업로드 | E2E (Playwright) | 실제 파일 전송이 필요하다 |
| 엑셀 업로드 | E2E (Playwright) | 실제 파일 전송이 필요하다 |
| 실제 달력 | E2E (Playwright) | 실제 브라우저에서 봐야 한다 |
| 체크박스 | E2E (Playwright) | 실제 브라우저에서 봐야 한다 |

## 주소만 알면 누구나

이웃거래 채팅에는 집 앞 사진, 송장, 계좌 캡처 같은 사진이 오간다.
이 사진들이 공개 버킷에 있었다. 주소만 알면 누구나 볼 수 있었다.

## 서명 URL은 어떻게 동작하나

해결책은 비공개 버킷과 서명 URL이다.

서명 URL은 주소에 "언제까지 유효한지"와 "서명"을 붙인 것이다.
S3 서명 URL을 열어 보면 `X-Amz-Date`(발급 시각), `X-Amz-Expires`(유효 시간), `X-Amz-Signature`(서명)가 붙어 있다.

서명은 비밀키로 만든다. 비밀키는 서버만 가지고 있다.
그래서 주소를 조금이라도 바꾸면 서명이 맞지 않고, 유효 시간이 지나면 S3가 거절한다.

## 서명은 "누가"를 모른다

여기서 놓치기 쉬운 게 있다.
S3는 서명과 시간만 본다. URL을 들고 온 사람이 누구인지는 모른다.
URL을 가진 사람이면 누구든 60초 동안 볼 수 있다.

그러니까 "누가 볼 수 있나"는 URL을 **발급할 때** 정해야 한다.
발급 API에서 요청한 사람이 그 채팅의 참여자인지 확인하고, 아니면 거절한다.

## 60초가 지나면 깨진다

서명 URL은 60초 뒤에 만료된다.
채팅방을 오래 띄워 두면 그 사이에 사진이 깨진다.

## 미리 갱신할까, 깨지면 고칠까

방법은 두 가지다.

- 만료되기 전에 미리 새 URL을 받아 둔다
- 깨지면 그때 새로 받는다

미리 받으면 화면에 보이지도 않는 사진까지 계속 재발급한다.
이미 화면에 그려진 이미지는 URL이 만료돼도 그대로 보인다. 다시 불러올 때만 문제가 된다.
그래서 깨졌을 때만 고치기로 했다.

## 깨진 것만, key당 한 번

이미지가 깨지면(`onError`) 그때 다시 발급받는다.
같은 key는 한 번만 재발급하고, 그래도 실패하면 깨진 이미지로 둔다. 무한히 다시 시도하지 않게.

여러 장이 동시에 깨질 수도 있다. 같은 시점에 받은 URL은 같은 시점에 만료되니까.
이때 요청이 장 수만큼 나가지 않게 `refetch({ cancelRefetch: false })`를 썼다.
이미 나가 있는 요청이 있으면 새로 보내지 않고 그걸 기다린다.

![사진 세 장이 동시에 깨져도 cancelRefetch false로 발급 요청은 한 번만 나가고, 그래도 실패하면 깨진 이미지로 두는 흐름](expiry.svg "동시에 깨져도 요청은 한 번")

```ts apps/mobile/hooks/useChatImageUrls.ts
// 로드 실패 시 같은 key는 1번만 재발급하고, 그래도 실패하면 깨진 이미지로 둠
const onErrorImage = async (key: string) => {
  if (retriedKeysRef.current.has(key)) {
    markAsBroken(key);
    return;
  }
  retriedKeysRef.current.add(key);
  const { isError: isRefetchError } = await refetch({ cancelRefetch: false });
  if (isRefetchError) markAsBroken(key);
};
```
