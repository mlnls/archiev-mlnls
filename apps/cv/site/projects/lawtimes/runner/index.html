들어갈 수 없는 서버에 배포하기

VPN IP만 받는 EC2에, 베스천에서 밖으로 나가는 연결만으로 배포했습니다.

5단계 → 머지 1번사람이 하는 일

  1. 01SSR이 꺼져 있던 렌더링
  2. 02페이지뷰가 빠지고 있었다
  3. 03들어갈 수 없는 서버에 배포하기
  4. 04실패해도 서비스는 살아 있게
  5. 05배포 권한은 레포 권한만큼만
  6. 06버전과 릴리스 노트도 자동으로

문제

  • 배포는 맥에서 크로스 빌드 → VPN 접속 → 베스천 SSH → 컨테이너 하나씩 교체 → git 싱크의 다섯 단계 손작업이었다.
  • EC2는 VPN IP만 받는데 GitHub 러너 IP는 매번 바뀐다. 진짜 질문은 “못 들어오는 서버에 어떻게 배포하나”였다.

해결

  • 베스천에 self-hosted runner를 두고 GitHub으로 나가는 443 롱 폴링만 쓰게 했다. VPN 규칙은 그대로다.
  • 빌드는 GitHub에서 amd64 네이티브로 하고, 버전은 최신 태그와 PR 라벨로 정한다.

결과

  • main · dev에 머지하면 배포된다.
  • pem · VPN · 비밀번호를 사람끼리 주고받지 않는다.

메모

  • 새 브랜치를 push하면 paths 필터가 비교할 커밋이 없어 아무 기록 없이 건너뛴다.
