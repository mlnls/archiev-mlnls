법률신문 한국법조인대관 · 노트 04 / 06

실패해도 서비스는 살아 있게

포트를 하나씩 교체하고, 응답이 없으면 그 포트만 이전 컨테이너로 되돌립니다.

약 8초테스트 서버 교체

  1. 01SSR이 꺼져 있던 렌더링
  2. 02페이지뷰가 빠지고 있었다
  3. 03들어갈 수 없는 서버에 배포하기
  4. 04실패해도 서비스는 살아 있게
  5. 05배포 권한은 레포 권한만큼만
  6. 06버전과 릴리스 노트도 자동으로

문제

  • 자동화해도 실패 경로가 코드에 없으면 기존 컨테이너가 멈춘 채로 끝난다.

해결

  • 기존 컨테이너는 지우지 않고 멈춰서 -old로 보관한 뒤 새 컨테이너를 띄운다.
  • 60초 안에 응답이 없으면 그 포트만 이전 컨테이너로 되돌리고, 다음 포트는 건드리지 않는다.

결과

  • 테스트 서버 교체는 정지부터 새 컨테이너 응답까지 약 8초, 운영은 무중단
  • 버전만 입력하면 롤백된다.

메모

  • set -e는 복구 단계까지 건너뛴다. 실패하면 기존 컨테이너가 멈춘 채 끝나서 if ! ...; then restore로 바꿨다.
  • 버전은 push한 순간 “쓴 것”이다. 같은 번호로 다시 빌드하면 롤백을 보장할 수 없다.
