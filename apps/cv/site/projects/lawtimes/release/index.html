법률신문 한국법조인대관 · 노트 06 / 06

버전과 릴리스 노트도 자동으로

PR 라벨로 버전을 정하고, 배포가 끝나면 GitHub Release에 변경 내역을 남깁니다.

PR 라벨버전 결정

  1. 01SSR이 꺼져 있던 렌더링
  2. 02페이지뷰가 빠지고 있었다
  3. 03들어갈 수 없는 서버에 배포하기
  4. 04실패해도 서비스는 살아 있게
  5. 05배포 권한은 레포 권한만큼만
  6. 06버전과 릴리스 노트도 자동으로

문제

  • 버전 번호와 변경 내역을 사람이 정하고 적어야 했다.

해결

  • PR 라벨(release:major · release:minor, 없으면 patch)로 다음 버전을 정한다.
  • 배포가 끝나면 태그를 붙이고 GitHub Release에 변경 내역을 남긴다.

결과

  • 운영 버전과 변경 내역이 Release 목록에 쌓인다. 이 흐름은 이후 사내 CLI의 bc deploy로 옮겼다.
