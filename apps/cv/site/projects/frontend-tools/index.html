01문제와 결과

문제

  • 앱·데스크톱 요청이 들어와도 CLI는 웹(React · Next)만 만들어, Expo · Electron은 매번 손으로 세팅했고 폴더 구조와 API 규칙이 프로젝트마다 달라졌습니다.
  • 배포 방식이 프로젝트마다 제각각이고 릴리즈 노트는 손으로 쓰거나 아예 남지 않아, 지금 운영에 어떤 버전이 떠 있는지 물어봐야 알았습니다.

결과

  • bc init 하나로 웹·앱·데스크톱 4종이 같은 폴더 구조, API 레이어, 린트 설정으로 시작합니다.
  • bc deploy 한 번이면 배포 workflow가 생기고, 배포가 성공했을 때만 태그와 Release가 남아 최신 Release가 곧 운영 버전입니다.

02한 일

  1. 01

    Desktop (Electron)

    electron-vite로 main · preload · renderer를 나누고, contextIsolation과 sandbox를 켠 채 preload에서 window.api만 노출했습니다. renderer는 웹과 같은 폴더 구조 · 토큰 · API 레이어를 쓰고, electron-builder로 macOS · Windows 설치 파일을 만듭니다.

  2. 02

    Mobile (Expo)

    create-expo-app 위에 사내 설정을 덮고, 앱 이름 · 번들 ID · 딥링크 scheme을 물어 app.config.ts에 적습니다. EAS에 로그인돼 있으면 projectId까지 연결하고, NativeWind · TanStack Query · axios를 기본으로 갖춥니다.

  3. 03

    bc deploy

    질문 4개(Enter면 기본값)로 배포 workflow를 만듭니다. 릴리즈 단계는 배포가 성공해야만 이어져 실패한 배포는 기록되지 않고, Slack 웹훅은 Secret 이름만 저장합니다. 법조인대관에서 먼저 운영한 흐름을 모든 프로젝트로 옮겼습니다.

  4. 04

    릴리즈 노트 패키지

    공통 settings 패키지에 byuckchon-release-notes를 더해, 이전 태그 이후 커밋을 기능 · 수정으로 묶고 날짜 버전(web@2026.11.05, 같은 날 재배포는 .2)으로 태그합니다. 커밋 분류는 PR 본문 자동 작성과 같은 코드를 씁니다.

  5. 05

    v3 정리 · 버전 검사

    쓰지 않는 채팅과 생성 질문을 걷어내 5,923줄과 의존성 9개를 지우고, npm 최신과 버전이 다르면 실행을 멈춰 옛 템플릿으로 만든 프로젝트가 생기지 않게 했습니다.

  6. 06

    공통 패키지 QA

    1월 31일에서 다음 달로 가면 3월이 되던 달력, SSR에서 SanitizeHtml 크래시, 입력 검증 정규식 오류 등 결함 12건을 고쳐 changeset으로 배포했습니다.

03배운 것

  • 배포 기록은 '배포 성공'에 묶어야 믿을 수 있습니다. 릴리즈를 배포 뒤에만 실행되게 걸어, 실패한 배포가 Release로 남지 않게 했습니다.
  • Release CI에서 npm 11로 만든 lockfile이 Node 20의 npm ci에서 실패했습니다. npm 10으로 다시 만들어 두 버전 모두 통과시켰습니다.
