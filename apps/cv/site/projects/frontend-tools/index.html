01문제와 결과

문제

  • CLI는 프로젝트를 만든 뒤에는 할 일이 없어, Figma · Swagger · 컨벤션 문서를 매번 따로 열어 AI에 설명했습니다.
  • PR마다 같은 컨벤션 지적을 사람이 반복했고, ESLint · tsconfig 사본이 프로젝트마다 달라졌습니다.
  • 시간이 지나자 init마다 묻는 질문과 채팅 기능은 쓰이지 않았고, 오래된 설치본으로 만든 프로젝트는 템플릿이 어긋났습니다.
  • 공통 패키지는 사용처에서 버그가 하나씩 보고되고 있었습니다.

결과

  • 모든 프로젝트가 같은 버전의 CLI로 생성되고, 규칙이 바뀌면 settings 버전만 올리면 됩니다.
  • 사람 리뷰는 기계적인 지적 대신 설계에 집중합니다.

02한 일

  1. 01

    문맥 등록

    bc.config.json에 Figma · API · 문서를 등록해 AI가 프로젝트를 알고 작업하게 했습니다 (v1.4 → v2.0).

  2. 02

    PR 봇

    변경 줄에 컨벤션 위반을 인라인 댓글로 달고, 커밋에서 PR 본문을 자동으로 씁니다. 설정은 settings 패키지 한 곳에서 관리합니다.

  3. 03

    v3 정리

    쓰지 않는 채팅과 생성 질문을 걷어내 의존성 9개, 5,923줄을 지웠습니다.

  4. 04

    버전 검사

    npm 최신보다 patch 하나라도 뒤처지면 업데이트 안내 후 멈춰, 어긋난 프로젝트가 생기지 않게 했습니다.

  5. 05

    스타터 확장

    Next · React에 더해 React Native(Expo)와 Electron, HTTP 에러 처리와 Sentry, 라이트 · 다크 테마를 기본으로 갖추게 했습니다.

  6. 06

    공통 패키지 QA

    1월 31일에서 다음 달로 가면 3월이 되던 달력, KST에서 달이 밀리던 문제, SSR에서 SanitizeHtml 크래시, 이메일 · 생년월일 · 주민번호 정규식 오류를 고쳐 changeset으로 배포했습니다.

03배운 것

  • Release CI에서 npm 11로 만든 lockfile이 Node 20의 npm ci에서 실패했습니다. npm 10으로 다시 만들어 두 버전 모두 통과시켰습니다.
  • 도구를 늘리기보다, 팀이 실제로 쓰는 것만 남기고 어긋날 틈을 막는 쪽을 택했습니다.
