한쪽만 바꾸면 상대편이 깨졌다

마켓:D는 관리자, 사용자 앱, 웹뷰가 각자 다른 레포에 있었다.

사용자 앱은 웹뷰를 띄운다.
그리고 둘은 메시지를 주고받는다. 웹뷰가 "로그인 화면으로 보내 줘"라고 하면 앱이 화면을 바꾸는 식이다.

앱과 웹뷰는 문자열로 대화한다

웹뷰와 앱 사이에는 함수 호출이 없다.
웹뷰는 window.ReactNativeWebView.postMessage로 문자열을 보내고, 앱은 onMessage로 받는다.
반대 방향도 마찬가지다.

그래서 둘 사이의 약속은 결국 "어떤 type 문자열을 보낼 것인가"다.
WEB_LOGOUT을 보내기로 했으면 양쪽이 정확히 같은 글자를 써야 한다.

문제는 이 약속이 양쪽 레포에 따로 적혀 있었다는 것이다.
앱에서 메시지 이름을 바꾸면 웹뷰는 그걸 모른다. 타입 검사도 레포를 넘어가지 못한다.
결과는 예고 없이 깨진 기능이었다. 반대도 마찬가지였다.

약속을 한 곳에만 두기

pnpm workspace와 Turborepo로 세 레포를 하나로 합쳤다.
그리고 양쪽이 같이 쓰는 것들을 공통 패키지로 뺐다.

두 앱에 흩어져 있던 메시지 이름은 합집합으로 모아 하나로 만들었다.

packages/constants/src/webview-message.tsTypeScript
/**
 * Webview <-> React Native 앱 사이의 postMessage 계약(contract).
 *
 * - WEB_MSG: webview 가 RN 으로 보내는 메시지의 type
 * - APP_MSG: RN 이 webview 로 보내는 메시지의 type
 *
 * webview / mobile 양쪽이 반드시 동일한 키 셋을 공유해야 하므로
 * 두 앱에 흩어져 있던 정의를 합집합으로 통합한 단일 소스입니다.
 */
export const WEB_MSG = Object.freeze({
  READY: 'READY',
  LOGOUT: 'WEB_LOGOUT',
  GO_TO_LOGIN: 'WEB_GO_TO_LOGIN',
  // ...
});

공통 설정과 env schema도 같은 식으로 뺐다.

이제는 빌드가 먼저 깨진다

이제 메시지 이름을 바꾸면 그걸 쓰는 앱과 웹뷰 코드가 같은 워크스페이스에서 바로 타입 에러를 낸다.
운영에서 깨지기 전에 빌드에서 깨진다.

모든 앱도 한 워크스페이스에서 같이 실행한다.
