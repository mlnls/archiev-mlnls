주소만 알면 누구나

이웃거래 채팅에는 집 앞 사진, 송장, 계좌 캡처 같은 사진이 오간다.
이 사진들이 공개 버킷에 있었다. 주소만 알면 누구나 볼 수 있었다.

서명 URL은 어떻게 동작하나

해결책은 비공개 버킷과 서명 URL이다.

서명 URL은 주소에 "언제까지 유효한지"와 "서명"을 붙인 것이다.
S3 서명 URL을 열어 보면 X-Amz-Date(발급 시각), X-Amz-Expires(유효 시간), X-Amz-Signature(서명)가 붙어 있다.

서명은 비밀키로 만든다. 비밀키는 서버만 가지고 있다.
그래서 주소를 조금이라도 바꾸면 서명이 맞지 않고, 유효 시간이 지나면 S3가 거절한다.

서명은 "누가"를 모른다

여기서 놓치기 쉬운 게 있다.
S3는 서명과 시간만 본다. URL을 들고 온 사람이 누구인지는 모른다.
URL을 가진 사람이면 누구든 60초 동안 볼 수 있다.

그러니까 "누가 볼 수 있나"는 URL을 발급할 때 정해야 한다.
발급 API에서 요청한 사람이 그 채팅의 참여자인지 확인하고, 아니면 거절한다.

사진이 들어오는 길은 두 개

받는 쪽에서는 사진이 두 경로로 들어온다.
채팅방을 열 때 받는 메시지 목록, 그리고 소켓으로 들어오는 새 메시지.

목록에는 서명 URL이 같이 온다. 소켓 메시지에는 없다.
그래서 목록의 URL은 initialData로 넣고, 없으면 바로 발급받게 해서 두 경로를 쿼리 하나로 처리했다.

apps/mobile/hooks/useChatImageUrls.tsTypeScript
// NOTE: 메시지 목록으로 받은 서명 URL이 있으면 그대로 쓰고, 없으면(실시간 수신) API로 발급
const { data: signedUrls, isError, refetch } = useGetChatMessageImages(
  { chatRoomNo, messageNo },
  { initialData: imageSignedUrls ?? undefined },
);

배포 순서도 설계다

서버와 앱이 같이 바뀌는 작업이었다.
서버를 배포한 직후에 이 PR을 머지하지 않으면 둘 다 깨진다. 그래서 배포 순서까지 정해 두고 내보냈다.

결과

채팅 사진은 참여자만, 60초 동안 볼 수 있다.
보내는 쪽 코드는 한 줄도 바꾸지 않았다.
