크롤러가 빈 페이지를 보고 있었다

법무법인 로백스 홈페이지 · 1/5 · 0 → 680자 (첫 HTML 본문)

모든 주소가 같은 빈 HTML을 돌려주던 SPA를 서버에서 본문을 그리는 구조로 옮겼습니다.

문제

  • 모든 주소가 같은 2,090바이트 HTML을 돌려줘 제목과 설명이 전부 같았다.
  • GPTBot · ClaudeBot 같은 AI 크롤러는 JS를 실행하지 않아 빈 페이지를 보고 있었다.
  • Lighthouse SEO는 100점이라 SEO · GEO 지적서를 받기 전까지 드러나지 않았다.

해결

  • CRA SPA를 Next.js App Router로 옮겼다.
  • page는 메타데이터, Container는 데이터와 JSON-LD, View는 화면만 맡게 나눠 리뉴얼 화면을 그대로 이식했다.
  • 페이지마다 ISR · SSG · SSR · CSR 중 맞는 방식을 골랐다.

결과

  • 업무분야 페이지의 첫 HTML 본문 0 → 680자
  • JS 전송량 2,512KB → 251KB (−90%), 페이지 총 전송량 −86%, Total Blocking Time −61%
  • 같은 머신 · 같은 크롬에서 직접 잰 값이다.

메모

  • Lighthouse는 JS를 다 실행한 뒤 검사해서 크롤러 시점을 못 본다. 그래서 원본 HTML을 직접 셌다.
  • 'use client'도 서버에서 그려지지만, 마운트 뒤에 그리는 것은 서버 HTML에 없다.

법무법인 로백스 홈페이지

  1. 1. 크롤러가 빈 페이지를 보고 있었다
  2. 2. 옛 주소와 옛 도메인을 한 주소로
  3. 3. 관리자가 저장하면 바로 반영
  4. 4. AI가 사실을 그대로 가져가게
  5. 5. 사용자가 관리자 코드까지 받고 있었다
