문제

  • 모든 주소가 같은 2,090바이트 HTML을 돌려줘 제목과 설명이 전부 같았습니다.
  • GPTBot, ClaudeBot 같은 AI 크롤러는 JS를 실행하지 않아 사실상 빈 페이지를 보고 있었습니다.

한 일

페이지 구조
page는 메타데이터, Container는 데이터와 JSON-LD, View는 화면만 맡도록 나눠 리뉴얼 화면을 App Router로 통째로 옮겼습니다.
공식 주소 하나
레거시 주소 21개 패턴을 308로 보내고, canonical과 sitemap이 같은 함수에서 주소를 만들게 했습니다.
캐시는 태그로
관리자가 저장하면 revalidateTag로 해당 캐시만 비워 정적 성능과 최신성을 같이 지켰습니다.
같은 @id로 연결
법인 · 구성원 · 글을 JSON-LD 그래프로 묶고, 화면에 없는 정보는 채우지 않았습니다.
인용하기 좋은 문장
업무분야 맨 앞에 두 문장 요약과 <time dateTime>을 두어 AI가 사실을 그대로 가져가게 했습니다.
번들 분리
관리자까지 한 번에 받던 첫 진입 JS를 라우트 단위로 나눠 7.2MB에서 171KB로 줄였습니다.

결과

  • 같은 머신 · 같은 크롬에서 직접 잰 결과, JS 전송량 −90%, 페이지 총 전송량 −86%, Total Blocking Time −61%, 이미지 에셋 −92%.
  • 기존 도메인(lvx.co.kr)은 새 도메인으로 301 이전하고, 유튜브 링크만 넣으면 제목과 게시일이 채워지게 했습니다.

배운 것

  • Lighthouse 100점은 JS를 다 실행한 뒤 검사해 크롤러 시점을 못 봅니다. 그래서 원본 HTML을 직접 셌습니다.
  • 'use client'도 서버에서 그려지지만, 마운트 후에 그리는 것은 서버 HTML에 없습니다.
  • 크롤러는 상태 코드부터 읽습니다. soft 404, 308, noindex 헤더 하나가 검색 결과를 바꿉니다.
  • GEO는 SEO 위에 “그 페이지가 말하는 사실이 정확한가”가 더해진 일이었습니다.
